# LOSTORY 데이터 모델

**P0 구현 기준:** Flyway `V1`–`V25` · 2026-08-25

아래 “P0 구현 스키마”가 현재 서버와 migration의 기준이다. 뒤의 “초기 개념 모델”은 P1 검토를 위해 보존한 설계 메모이며, 같은 이름의 필드나 제약이 충돌하면 P0 구현 스키마를 따른다. 적용된 migration은 수정하지 않고 다음 버전으로만 보강한다.

## P0 구현 스키마

### 핵심 관계

```text
users 1 ── N found_items 1 ── N found_item_images
                         ├── N found_item_vision_jobs
                         └── N item_features
users 1 ── N lost_reports 1 ── N report_waypoints
                         └── N match_candidates N ── 1 found_items
lost_centers 1 ── N found_items
object_deletion_outbox: 객체 저장소 삭제 작업의 독립 재시도 큐
vision_daily_admissions: UTC 날짜별 Vision 작업 예약량
```

### found_items

| 필드 | 타입/제약 | P0 의미 |
|---|---|---|
| `id`, `finder_id` | bigint PK, users FK | 습득물·소유자 |
| `status` | text | `DRAFT`, `PENDING_HANDOVER`, `ACTIVE`, `EXPIRED`, `RETURNED` |
| `vision_status` | text | `PENDING`, `READY`, `FAILED` |
| `analysis_generation` | integer ≥ 0 | 사진 교체 때 증가하여 오래된 Vision 결과 차단 |
| `draft_expires_at` | timestamptz nullable | DRAFT 전용, 기본 생성 시각 + `PT24H` |
| `category`, `found_at`, 위치·설명 | DRAFT에서 nullable | 등록 확정 뒤 필수 |
| `storage_method` | text nullable | `LEFT_IN_PLACE`, `MOVED_TO_SAFE_PLACE`, `HANDED_TO_CENTER` |
| `storage_description` | text nullable | 안전 장소 이동일 때만 사용 |
| `center_id` | bigint FK nullable | 센터 인계일 때만 사용 |
| `handover_status` | text | `NONE`, `USER_CONFIRMED`, 내부 레거시 `LEGACY_UNVERIFIED` |
| `handed_at` | timestamptz nullable | 사용자 인계 확정의 서버 시각 |
| `legacy_handover_place_name` | text nullable | V19 이전 인계 데이터 보존, 신규 쓰기 금지 |
| `expired_at` | timestamptz nullable | 등록 후 기본 `P14D`; `expired_at <= now`면 후보 제외 |

상태와 보관 방식은 하나의 CHECK로 결합한다. 센터 선택 전에는 `PENDING_HANDOVER/NONE`, 사용자 확인 뒤에는 `ACTIVE/USER_CONFIRMED`다. 레거시 종료 행은 불변이며 `LEGACY_UNVERIFIED`를 사용자 확인으로 조작할 수 없다.

### found_item_images와 Vision

| 테이블 | 핵심 필드/제약 |
|---|---|
| `found_item_images` | `object_key`, `is_current`, `analysis_generation`, `upload_operation_id`, `object_deleted_at`; 항목당 현재 사진 하나의 partial unique index |
| `found_item_vision_jobs` | `(found_item_id,image_id,analysis_generation)` unique; `PENDING/PROCESSING/READY/FAILED/SUPERSEDED`, lease와 완료 시각 상태 CHECK |
| `vision_daily_admissions` | UTC `admission_date` PK, 음수가 아닌 `reserved_count`; 기본 일일 한도 100 |
| `item_features` | `COLOR/BRAND/LABEL/PUBLIC_DESCRIPTION/OCR_TEXT`; `FINDER` 우선, 그다음 AI; 결정적 선택을 위한 `(item_id,kind,source,visibility,ordinal,id)` index |

V19의 `legacy_storage_path`는 읽기·복구 판단용으로 유지하고 신규 업로드에는 쓰지 않는다. 교체·DRAFT 정리·종료 미디어 정리에서 삭제할 객체는 DB transaction 안에서 `object_deletion_outbox`에 먼저 기록한다.

### object_deletion_outbox

| 필드 | 제약/운영 의미 |
|---|---|
| `object_key` | 비어 있지 않은 삭제 대상 |
| `idempotency_key` | unique, 동일 삭제 중복 방지 |
| `status` | `PENDING`, `PROCESSING`, `DONE` |
| `attempt_count`, `next_attempt_at` | 재시도 횟수와 다음 실행 시각 |
| `lease_owner`, `lease_until` | PROCESSING일 때만 필수 |
| `last_error_code`, `last_error` | 안전한 실패 분류와 진단 |
| `completed_at` | DONE일 때만 필수 |

worker는 lease를 획득하고 삭제를 멱등 실행한다. 실패는 backoff 뒤 재시도하며 DB 행 삭제 성공을 객체 삭제 성공으로 추정하지 않는다.

### lost_reports, report_waypoints, match_candidates

| 테이블 | P0 보강 필드/제약 |
|---|---|
| `lost_reports` | `effective_search_radius_meters` 500–3000, `radius_policy_version`, JSON 배열 `center_guidance`, `candidates_stale`, `last_matched_at`, `matching_policy_version`, 상태 `OPEN/CLOSED/EXPIRED` |
| `report_waypoints` | 신고별 1–10개 순서 핀, 중복 좌표 제거 |
| `match_candidates` | 신고·순위와 신고·습득물 unique, score 0–100, private `score_breakdown`, 정책 버전 |

반경은 인접 핀 거리 중앙값에 `1000 + 0.10 × median`을 적용해 500–3000 m로 제한하고 최종 미터만 `HALF_UP` 반올림한다. 후보 점수는 위치/시간/분류/색상/설명 `0.35/0.20/0.20/0.15/0.10`이며 최종값만 소수 둘째 자리 `HALF_UP`이다. 후보는 `ACTIVE AND expired_at > database_now`만 대상으로 하고 score DESC, FoundItem ID ASC로 최대 5개를 교체한다.

## Entity 정의

### 사용자 (User)

사용자 테이블 작성 (users)

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- email (`text`)
  - UNIQUE
  - NOT NULL
- password_hash (`text`)
  - NOT NULL
  > 해싱 알고리즘이나 설정이 변하면 길이가 변할 수 있으므로 text 사용
- display_name (`varchar(50)`)
  - NOT NULL
- status (`text`)
  - NOT NULL
  - DEFAULT ‘ACTIVE’
  > 💡`enum` UserStatus
  >
  > - ACTIVE : 활성 사용자
  > - BLOCKED : 악의적인 이용으로 차단당한 사용자
- role (`text`)
  - NOT NULL
  - DEFAULT ‘USER’
  > 💡`enum` UserRole
  >
  > - USER : 일반 사용자 계정 (센터 관리자도 포함)
  > - ADMIN : 서비스 관리자 계정
  >
  > 센터 관리자는 role = USER로 설정하고, LostCenter.manager_id = [user.id](http://user.id)인 경우에 해당 센터의 관리자인 것으로 판정하면 될 것 같아요.  
  > 굳이 CENTER라는 role 값을 만들 필요는 없어보여요~
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()
- updated_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
CHECK (email = btrim(email) AND char_length(email) BETWEEN 3 AND 320)
CHECK (btrim(display_name) <> '')
CHECK (status IN ('ACTIVE', 'BLOCKED'))
CHECK (role IN ('USER', 'ADMIN'))

CREATE UNIQUE INDEX users_email_ci_uq ON users (lower(email));

```

### 습득물 (FoundItem)

> 💡`status`를 통해 이 습득물이 유효한지 아닌지를 확인할 수 있어요. [26.8.11]  
> 또, 이 습득물이 어떻게 보관되었는지는 storage_method를 읽고, 이후 관련 필드들 (`storage_desc`, `center_id`)를 유형에 맞게 읽는 방식으로 사용해야 해요.

습득물 테이블 (found_items)

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- finder_id (`bigint`) : FK
  - NOT NULL
  - REFERENCES users(id)
  - ON DELETE RESTRICT
- category ( `varchar(64)` )
  - NOT NULL
- found_at (`timestamptz`)
  - NOT NULL

  DEFAULT NOW()를 쓰는 대신 사진의 메타데이터나 api 호출 시점 등을 우선 사용하기?
- found_location ( `geography(Point, 4326)` )
  - NOT NULL
- status (`text`)
  - NOT NULL
  - DEFAULT ‘ACTIVE’
  > 💡`enum` FoundItemStatus
  >
  > - ACTIVE : 매칭 가능한, 유효한 습득물
  > - EXPIRED : 매칭 불가능한, 더 이상 유효하지 않은 습득물
  > - RETURNED : 주인에게 반환된 물건
- storage_method (`text`)
  - NOT NULL
  > 💡`enum` StorageMethod
  >
  > - LEFT_IN_PLACE = 습득 장소에 그대로 둠
  > - MOVED_TO_SAFE_PLACE = 인근의 안전한 장소로 옮김 (분실물 센터가 아닌 경우)
  > - HANDED_TO_CENTER = 분실물 센터로 인계함
- storage_desc (`text`)
  > storage_method = ‘MOVED_TO_SAFE_PLACE’ 일 때에만 사용되는 필드에요.
- center_id (`bigint`)
  > storage_method = ‘HANDED_TO_CENTER’ 일 때에만 사용되는 필드에요.
  - REFERENCES lost_centers(id)
  - ON DELETE RESTRICT
- expired_at (`timestamptz`)
  > 1. 센터에 인계되지 않았다면, 자연적으로 더 이상 습득물 정보를 신뢰하기 어려운 기간 (1주?)이 지나면 이 정보를 만료시킴
  > 2. 센터에 인계되었다면, 센터 측의 보관 기간만큼 다시 갱신함. 이후에 기간이 지난다면 만료 처리.
  - NOT NULL
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()
- updated_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
CHECK (btrim(category) <> '')
CHECK (status IN ('ACTIVE', 'EXPIRED', 'RETURNED'))
CHECK (
  (
      storage_method = 'LEFT_IN_PLACE'
      AND storage_desc IS NULL
      AND center_id IS NULL
  )
  OR (
      storage_method = 'MOVED_TO_SAFE_PLACE'
      AND storage_desc IS NOT NULL
      AND btrim(storage_desc) <> ''
      AND char_length(storage_desc) <= 500
      AND center_id IS NULL
  )
  OR (
      storage_method = 'HANDED_TO_CENTER'
      AND storage_desc IS NULL
      AND center_id IS NOT NULL
  )
);

```

습득물 이미지 테이블 (found_item_images): 하나의 습득물에 대해 여러 장의 사진을 Object Storage에 저장하기 위한 정보 매핑 테이블

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- item_id (`bigint`) : FK
  - NOT NULL
  - REFERENCES found_items(id)
  - ON DELETE CASCADE
- storage_key (`text`)
  - NOT NULL
- thumbnail_storage_key (`text`)
- content_type (`text`)
  - NOT NULL
- byte_size (`integer`)
  - NOT NULL
- sha256 (`bytea`)
  - NOT NULL
  > `bytea` 는 PostgreSQL의 이진 데이터 타입이래요. 바이트 배열을 그대로 저장하기 위한 타입이고, sha256 해시값은 내부 검증용이라 그냥 바이트 값을 바로 쓰는게 나아보여요.
- sort_order (`smallint`)
  - NOT NULL
  - DEFAULT 0
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
UNIQUE (storage_key)
UNIQUE (thumbnail_storage_key)
UNIQUE (item_id, sort_order)
CHECK (content_type IN ('image/jpeg', 'image/png', 'image/webp'))
CHECK (byte_size BETWEEN 1 AND 10485760)
CHECK (octet_length(sha256) = 32)
CHECK (sort_order >= 0)

```

추출된 습득물 특징을 저장하는 테이블 (item_features)

> 하나의 습득물에 대해, ItemFeature는 여러개 존재하며 각 행에는 한가지 특징을 저장해요.

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- item_id (`bigint`) : FK
  - NOT NULL
  - REFERENCES found_items(id)
  - ON DELETE CASCADE
- kind (`text`) : 물건의 보조 특징 분류 (색상인지, 브랜드인지, …)
  - NOT NULL
- feature_value (`text`) : 이 특징의 실제 값
  - NOT NULL
- ordinal (`smallint`) : 같은 종류의 특징이 여러 개 일때 배치 순서
  - NOT NULL
  - DEFAULT 1
- source (`text`) : 이 특징 정보를 만든 주체/방식
  - NOT NULL
  > 💡`enum` ItemFeatureSource
  >
  > - FINDER : 습득자가 직접 입력한 정보
  > - AI : Vision 및 AI 기술 기반으로 추출된 정보
  > - SYSTEM : 관리자가 입력한 정보
- visibility (`text`) : 후보 열람 화면에서 신고자가 볼 수 있는지
  - NOT NULL
  - DEFAULT ‘MATCH_ONLY’
  > 💡`enum` ItemFeatureVisibility
  >
  > - MATCH_ONLY : 매칭 과정에서만 사용되는 정보로, 신고자에게는 보여지지 않음
  > - CANDIDATE_VIEW : 신고자가 포인트로 열람 권한을 얻을 시 볼 수 있음
- confidence ( `numeric(4, 3)` ) : AI가 추출한 특징인 경우, 이 정보의 신뢰도
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
UNIQUE (item_id, kind, source, ordinal)
CHECK (kind IN ('COLOR', 'BRAND', 'PUBLIC_DESCRIPTION', 'OCR_TEXT'))
CHECK (visibility IN ('MATCH_ONLY', 'CANDIDATE_VIEW'))
CHECK (source IN ('FINDER', 'AI', 'SYSTEM'))
CHECK (confidence IS NULL OR confidence BETWEEN 0 AND 1)
CHECK (ordinal BETWEEN 1 AND 20)
CHECK (btrim(feature_value) <> '')

```

### 분실 신고 (LostReport)

분실 신고 테이블 (lost_reports)

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- reporter_id (`bigint`) : FK
  - NOT NULL
  - REFERENCES users(id)
  - ON DELETE RESTRICT

  - NOT NULL

  - NOT NULL
- description (`text`)
  - NOT NULL
- search_radius (`integer`) : m 단위의 검색 범위
  - NOT NULL
  - DEFAULT 1000
- status (`text`)
  - NOT NULL
  - DEFAULT ‘OPEN’
  > 💡`enum` LostReportStatus
  >
  > - OPEN : 분실 신고 상태. 아직 회수하기 전
  > - CLOSED : 분실물을 회수함.
  > - EXPIRED : 분실물을 회수하지 못했으나 기간이 만료됨.
- expired_at (`timestamptz`)
  - NOT NULL
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()
- updated_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
UNIQUE (id, reporter_id)
CHECK (btrim(category) <> '')
CHECK (btrim(description) <> '' AND char_length(description) <= 1000)
CHECK (lost_at_from <= lost_at_to)
CHECK (search_radius BETWEEN 100 AND 3000)
CHECK (status IN ('OPEN', 'CLOSED', 'EXPIRED'))
CHECK (expired_at > created_at)

```

  > 클라이언트의 중복 요청을 방지할 고유한 값이에요.  
  > 위의 id값은 transaction의 id처럼 쓰여서, 같은 작업이 여러번 진행될 경우 이 id값은 중복을 방지하지 못해요.
  - NOT NULL
  - UNIQUE
- reason (text)
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

UNIQUE (idempotency_key)
CHECK (
  (entry_type = 'DEMO_GRANT' AND amount > 0)
  OR (entry_type = 'CANDIDATE_ACCESS_DEBIT' AND amount < 0)
  OR (entry_type = 'ADMIN_ADJUSTMENT' AND amount <> 0)

CHECK (
  entry_type <> 'ADMIN_ADJUSTMENT'
