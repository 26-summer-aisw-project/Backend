## Entity 정의

### 사용자 (User)

사용자 테이블 작성 (users)

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- email (`text`)
  - UNIQUE
  - NOT NULL
- password_hash (`text`)
  - NOT NULL
  > 해싱 알고리즘이나 설정이 변하면 길이가 변할 수 있으므로 text 사용
- display_name (`varchar(50)`)
  - NOT NULL
- status (`text`)
  - NOT NULL
  - DEFAULT ‘ACTIVE’
  > 💡`enum` UserStatus
  >
  > - ACTIVE : 활성 사용자
  > - BLOCKED : 악의적인 이용으로 차단당한 사용자
- role (`text`)
  - NOT NULL
  - DEFAULT ‘USER’
  > 💡`enum` UserRole
  >
  > - USER : 일반 사용자 계정 (센터 관리자도 포함)
  > - ADMIN : 서비스 관리자 계정
  >
  > 센터 관리자는 role = USER로 설정하고, LostCenter.manager_id = [user.id](http://user.id)인 경우에 해당 센터의 관리자인 것으로 판정하면 될 것 같아요.  
  > 굳이 CENTER라는 role 값을 만들 필요는 없어보여요~
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()
- updated_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
CHECK (email = btrim(email) AND char_length(email) BETWEEN 3 AND 320)
CHECK (btrim(display_name) <> '')
CHECK (status IN ('ACTIVE', 'BLOCKED'))
CHECK (role IN ('USER', 'ADMIN'))

CREATE UNIQUE INDEX users_email_ci_uq ON users (lower(email));

```

### 분실물 센터 (LostCenter)

> 💡 D0 기준으로는, ‘서비스 내에서 검색될 수 있는 모든 분실물 센터’의 목록이에요.  
> 디렉터리 센터/파트너 센터의 구분 없이 분실물 센터에 대한 최소한의 정보만 가지고 있는 테이블이에요.

> ❗파트너 센터에 대해서는 정보를 어떻게 저장하고 관리할지 더 고민해봐야겠어요.

분실물 센터 테이블 작성 (lost_centers)

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- name (`text`)
  - NOT NULL
- address (`text`)
  - NOT NULL
- location ( `geography(Point, 4326)` )
  - NOT NULL
- contact_phone (`text`)
  - NOT NULL
- operating_hours (`text`)
  - NOT NULL
- is_active (`boolean`)
  - NOT NULL
  - DEFAULT TRUE
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()
- updated_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
UNIQUE (source_key)
CHECK (btrim(name) <> '')
CHECK (btrim(address) <> '')
CHECK (contact_phone = btrim(contact_phone))

```

### 습득물 (FoundItem)

> 💡`status`를 통해 이 습득물이 유효한지 아닌지를 확인할 수 있어요. [26.8.11]  
> 또, 이 습득물이 어떻게 보관되었는지는 storage_method를 읽고, 이후 관련 필드들 (`storage_desc`, `center_id`)를 유형에 맞게 읽는 방식으로 사용해야 해요.

습득물 테이블 (found_items)

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- finder_id (`bigint`) : FK
  - NOT NULL
  - REFERENCES users(id)
  - ON DELETE RESTRICT
- category ( `varchar(64)` )
  - NOT NULL
- found_at (`timestamptz`)
  - NOT NULL

  DEFAULT NOW()를 쓰는 대신 사진의 메타데이터나 api 호출 시점 등을 우선 사용하기?
- found_location ( `geography(Point, 4326)` )
  - NOT NULL
- status (`text`)
  - NOT NULL
  - DEFAULT ‘ACTIVE’
  > 💡`enum` FoundItemStatus
  >
  > - ACTIVE : 매칭 가능한, 유효한 습득물
  > - EXPIRED : 매칭 불가능한, 더 이상 유효하지 않은 습득물
  > - RETURNED : 주인에게 반환된 물건
- storage_method (`text`)
  - NOT NULL
  > 💡`enum` StorageMethod
  >
  > - LEFT_IN_PLACE = 습득 장소에 그대로 둠
  > - MOVED_TO_SAFE_PLACE = 인근의 안전한 장소로 옮김 (분실물 센터가 아닌 경우)
  > - HANDED_TO_CENTER = 분실물 센터로 인계함
- storage_desc (`text`)
  > storage_method = ‘MOVED_TO_SAFE_PLACE’ 일 때에만 사용되는 필드에요.
- center_id (`bigint`)
  > storage_method = ‘HANDED_TO_CENTER’ 일 때에만 사용되는 필드에요.
  - REFERENCES lost_centers(id)
  - ON DELETE RESTRICT
- expired_at (`timestamptz`)
  > 1. 센터에 인계되지 않았다면, 자연적으로 더 이상 습득물 정보를 신뢰하기 어려운 기간 (1주?)이 지나면 이 정보를 만료시킴
  > 2. 센터에 인계되었다면, 센터 측의 보관 기간만큼 다시 갱신함. 이후에 기간이 지난다면 만료 처리.
  - NOT NULL
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()
- updated_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
CHECK (btrim(category) <> '')
CHECK (status IN ('ACTIVE', 'EXPIRED', 'RETURNED'))
CHECK (
  (
      storage_method = 'LEFT_IN_PLACE'
      AND storage_desc IS NULL
      AND center_id IS NULL
  )
  OR (
      storage_method = 'MOVED_TO_SAFE_PLACE'
      AND storage_desc IS NOT NULL
      AND btrim(storage_desc) <> ''
      AND char_length(storage_desc) <= 500
      AND center_id IS NULL
  )
  OR (
      storage_method = 'HANDED_TO_CENTER'
      AND storage_desc IS NULL
      AND center_id IS NOT NULL
  )
);

```

습득물 이미지 테이블 (found_item_images): 하나의 습득물에 대해 여러 장의 사진을 Object Storage에 저장하기 위한 정보 매핑 테이블

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- item_id (`bigint`) : FK
  - NOT NULL
  - REFERENCES found_items(id)
  - ON DELETE CASCADE
- storage_key (`text`)
  - NOT NULL
- thumbnail_storage_key (`text`)
- content_type (`text`)
  - NOT NULL
- byte_size (`integer`)
  - NOT NULL
- sha256 (`bytea`)
  - NOT NULL
  > `bytea` 는 PostgreSQL의 이진 데이터 타입이래요. 바이트 배열을 그대로 저장하기 위한 타입이고, sha256 해시값은 내부 검증용이라 그냥 바이트 값을 바로 쓰는게 나아보여요.
- sort_order (`smallint`)
  - NOT NULL
  - DEFAULT 0
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
UNIQUE (storage_key)
UNIQUE (thumbnail_storage_key)
UNIQUE (item_id, sort_order)
CHECK (content_type IN ('image/jpeg', 'image/png', 'image/webp'))
CHECK (byte_size BETWEEN 1 AND 10485760)
CHECK (octet_length(sha256) = 32)
CHECK (sort_order >= 0)

```

추출된 습득물 특징을 저장하는 테이블 (item_features)

> 하나의 습득물에 대해, ItemFeature는 여러개 존재하며 각 행에는 한가지 특징을 저장해요.

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- item_id (`bigint`) : FK
  - NOT NULL
  - REFERENCES found_items(id)
  - ON DELETE CASCADE
- kind (`text`) : 물건의 보조 특징 분류 (색상인지, 브랜드인지, …)
  - NOT NULL
- feature_value (`text`) : 이 특징의 실제 값
  - NOT NULL
- ordinal (`smallint`) : 같은 종류의 특징이 여러 개 일때 배치 순서
  - NOT NULL
  - DEFAULT 1
- source (`text`) : 이 특징 정보를 만든 주체/방식
  - NOT NULL
  > 💡`enum` ItemFeatureSource
  >
  > - FINDER : 습득자가 직접 입력한 정보
  > - AI : Vision 및 AI 기술 기반으로 추출된 정보
  > - SYSTEM : 관리자가 입력한 정보
- visibility (`text`) : 후보 열람 화면에서 신고자가 볼 수 있는지
  - NOT NULL
  - DEFAULT ‘MATCH_ONLY’
  > 💡`enum` ItemFeatureVisibility
  >
  > - MATCH_ONLY : 매칭 과정에서만 사용되는 정보로, 신고자에게는 보여지지 않음
  > - CANDIDATE_VIEW : 신고자가 포인트로 열람 권한을 얻을 시 볼 수 있음
- confidence ( `numeric(4, 3)` ) : AI가 추출한 특징인 경우, 이 정보의 신뢰도
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
UNIQUE (item_id, kind, source, ordinal)
CHECK (kind IN ('COLOR', 'BRAND', 'PUBLIC_DESCRIPTION', 'OCR_TEXT'))
CHECK (visibility IN ('MATCH_ONLY', 'CANDIDATE_VIEW'))
CHECK (source IN ('FINDER', 'AI', 'SYSTEM'))
CHECK (confidence IS NULL OR confidence BETWEEN 0 AND 1)
CHECK (ordinal BETWEEN 1 AND 20)
CHECK (btrim(feature_value) <> '')

```

### 분실 신고 (LostReport)

분실 신고 테이블 (lost_reports)

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- reporter_id (`bigint`) : FK
  - NOT NULL
  - REFERENCES users(id)
  - ON DELETE RESTRICT
- category ( `varchar(64)` )
  - NOT NULL
- lost_at_from (`timestamptz`)
  - NOT NULL
- lost_at_to (`timestamptz`)
  - NOT NULL
- description (`text`)
  - NOT NULL
- search_radius (`integer`) : m 단위의 검색 범위
  - NOT NULL
  - DEFAULT 1000
- status (`text`)
  - NOT NULL
  - DEFAULT ‘OPEN’
  > 💡`enum` LostReportStatus
  >
  > - OPEN : 분실 신고 상태. 아직 회수하기 전
  > - CLOSED : 분실물을 회수함.
  > - EXPIRED : 분실물을 회수하지 못했으나 기간이 만료됨.
- expired_at (`timestamptz`)
  - NOT NULL
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()
- updated_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
UNIQUE (id, reporter_id)
CHECK (btrim(category) <> '')
CHECK (btrim(description) <> '' AND char_length(description) <= 1000)
CHECK (lost_at_from <= lost_at_to)
CHECK (search_radius BETWEEN 100 AND 3000)
CHECK (status IN ('OPEN', 'CLOSED', 'EXPIRED'))
CHECK (expired_at > created_at)

```

### 포인트

  - PRIMARY KEY
  - REFERENCES users(id)
  - ON DELETE RESTRICT
- balance (integer) : 보유한 포인트 양
  - NOT NULL
  - DEFAULT 0
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()
- updated_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
CHECK (balance >= 0)

```

포인트 기록 테이블 (point_ledger)

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- user_id (`bigint`) : FK
  - NOT NULL
  - REFERENCES users(id)
  - ON DELETE RESTRICT
- entry_type (`text`)
  - NOT NULL
  > 💡`enum` PointEntryType
  >
  > - CANDIDATE_ACCESS_DEBIT : 후보 매칭 후 상세 정보 조회를 위해 포인트 사용
  > - ADMIN_ADJUSTMENT : 관리자 권한으로 수치 조정
  > - DEMO_GRANT : 포인트 획득 시나리오가 없는 단계에서 테스트용으로 사용하는 포인트 획득 수단
  >
  > 이후에 P1에서 포인트 획득 관련 시나리오를 구현하면서 추가해야 해요~
- amount (integer)
  - NOT NULL
- idempotency_key (uuid)
  > 클라이언트의 중복 요청을 방지할 고유한 값이에요.  
  > 위의 id값은 transaction의 id처럼 쓰여서, 같은 작업이 여러번 진행될 경우 이 id값은 중복을 방지하지 못해요.
  - NOT NULL
  - UNIQUE
- reason (text)
- created_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
UNIQUE (idempotency_key)
CHECK (
  (entry_type = 'DEMO_GRANT' AND amount > 0)
  OR (entry_type = 'CANDIDATE_ACCESS_DEBIT' AND amount < 0)
  OR (entry_type = 'ADMIN_ADJUSTMENT' AND amount <> 0)
)
CHECK (
  entry_type <> 'ADMIN_ADJUSTMENT'
  OR (reason IS NOT NULL AND btrim(reason) <> '')
)

```

### 감사 로그 (AuditLog)

감사 로그 테이블 작성 (audit_logs)

- id (`bigint`)
  - GENERATED BY DEFAULT AS IDENTITY
  - PRIMARY KEY
- user_id (`bigint`)
  - REFERENCES users(user_id)
  - ON DELETE SET NULL
- action (`text`)
  - NOT NULL
- target_type (`text`)
  > 💡`enum` AuditLogTargetType
  >
  > 사용자의 어떤 행동들을 기록해야 할까요?
  >
  > - LOST_REPORT
  > - ITEM_FOUND
  > - …
- target_id (`bigint`)
- metadata_json (`jsonb`)
  - NOT NULL
  - DEFAULT ‘{}’::jsonb
- occurred_at (`timestamptz`)
  - NOT NULL
  - DEFAULT NOW()

```sql
CHECK (action ~ '^[A-Z][A-Z0-9_]{2,63}$')
CHECK (
  (target_type IS NULL AND target_id IS NULL)
  OR (target_type IS NOT NULL AND target_id IS NOT NULL)
)
CHECK (jsonb_typeof(metadata_json) = 'object')

```
